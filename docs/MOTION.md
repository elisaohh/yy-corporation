# 모션 명세서 — YY CORPORATION 웹사이트

> 기준: 저장소 `main` 브랜치 코드(2026-10-19). 다른 플랫폼(카페24 등)에서 **같은 모션을 다시 구현**할 때의 기준 문서입니다.
> 숫자는 모두 실제 코드 값이고, 표의 "구현 파일"에 원본 코드가 있습니다. 화면으로 보는 기준은 실제 사이트입니다.
> 라이브러리: **GSAP 3.15 + ScrollTrigger**(CDN으로 어디서나 사용 가능). 나머지는 CSS transition · keyframes.

## 0. 공통 규칙

| 항목 | 값 |
|---|---|
| 기본 이징 (`--ease-yy-out`) | `cubic-bezier(0.22, 1, 0.36, 1)` — 빠르게 시작해 부드럽게 멈춤 |
| 전환 이징 (`--ease-yy-in-out`) | `cubic-bezier(0.65, 0, 0.35, 1)` |
| 시간 토큰 | fast 200ms · base 300ms · page 400ms · reveal 600ms |
| PC / 모바일 기준 | 레이아웃 768px(`md`) · 1200px(`lg`). **HOME 히어로 마우스 · 공정 모션 고정은 1024px 이상 + 마우스(pointer: fine)** |
| 동작 줄이기 | OS의 "동작 줄이기(prefers-reduced-motion: reduce)"가 켜져 있으면 **모든 모션을 끄고 완성된 화면을 바로 보여 줌**(CSS 전체 `transition/animation 0.01ms`, GSAP 모션은 시작하지 않음) |
| 검수용 | 주소에 `?still` → 로딩 · 등장 모션 · 공정 모션 고정 없이 완성 화면(캡처 · 피그마 가져오기용, 배포 사이트에서도 동작) |
| GSAP 기본 | `gsap.matchMedia()`로 PC · 모바일 · 동작 줄이기를 나눠 등록하고, 화면 크기가 바뀌면 자동으로 다시 등록 |

## 2. HOME

### 2-1. 로딩 → 히어로 (`home/HeroFloat.tsx`)

**순서(한 타임라인, 기본 이징 power3.out)**

| # | 동작 | 시간 |
|---|---|---|
| 1 | 로고가 아래에서 위로 차오름(clip-path `inset(100% 0 0 0)` → `inset(0)`, y 12 → 0) | 0.8s |
| 2 | 그대로 머무름 | 0.6s |
| 3 | 로고가 위로 18px 올라가며 사라짐 | 0.45s · power2.in |
| 4 | 흰 막이 위로 걷힘(yPercent 0 → −100) | 0.9s · power4.inOut, 3과 0.15s 겹침 |
| 5 | 그 뒤 차콜 막이 한 박자 늦게 따라 걷힘 | 0.9s · power4.inOut, 4보다 0.12s 늦게 |
| 6 | 사진 등장: 투명 · scale 1.04 · y 24 → 보임 · 1 · 0 | 1.6s · power2.out, 5와 0.5s 겹침 |
| 7 | 물방울 14개 등장: y 26 → 0, 무작위 순서 0.04s 간격 | 1.4s · power2.out, 6보다 0.2s 늦게 |
| 8 | 큰 제목 단어가 아래에서 올라옴(yPercent 110 → 0, 단어 마스크 안에서) 0.07s 간격 | 1.1s |
| 9 | 윗줄 문구 · 버튼: 투명 · y 14 → 보임 · 0, 0.08s 간격 | 0.8s |
| 10 | 떠다니기 시작(아래) | 9와 0.6s 겹침 |

- **건너뛰기**: 로딩 중 휠 · 터치 이동 · 키 입력이 있으면 즉시 완성 상태로.
- **떠다니기(무한 반복, sine.inOut · yoyo)** — 병 층과 물방울 각각, 가로 · 세로 · 회전을 **서로 다른 주기**로 돌려 매번 다른 궤적:

| 대상 | 세로 | 가로 | 회전 | 주기(무작위 범위) |
|---|---|---|---|---|
| 병 층 | −12px × 깊이 | ±6px × 깊이 | ±1.2° | 세로 4.5–5.5s · 가로 6–7.5s · 회전 5–8s |
| 물방울 | −14~−24px × 깊이 | ±12px × 깊이 | ±6° | 세로 3–4.6s · 가로 4.2–6.4s · 회전 5–8s |

  시작 지연 0–1.2s 무작위. 물방울 깊이 = `0.55 + min(0.75, 3 / 물방울폭%)` — 작은 물방울일수록 크게 움직임.
- **마우스 깊이감(PC, 1024px+ · 마우스)**: 커서 위치(화면 중앙 기준 −0.5~0.5)에 따라 x = 22px × 깊이, y = 16px × 깊이, 1.4s · power3.out로 따라감. 병 층 깊이 0.3.
- **스크롤**: 섹션이 화면 위로 빠져나가는 동안 물방울이 y −110px × (깊이 × 0.9), 병 층 −110 × 0.35로 올라감(scrub 0.6 — 물방울이 병보다 빨리 흘러감).
- 물방울은 `mix-blend-mode: multiply`로 합성(흰 바탕이 비치지 않게).

### 2-3. 공정 모션 (`home/ProcessMotion.tsx`, 데이터 `data/home.ts`)

**화면 구성**: 왼쪽 병(같은 좌표의 이미지 6장 겹침: 기본 병 + 코팅 · 인쇄 · 부식 · 라벨 + 스포이드), 오른쪽 공정 목록(COATING · PRINTING · ETCHING · LABELING · MATCH)과 노란 세로 진행 막대.

**PC (1024px 이상)** — 섹션을 화면에 고정(pin)하고 스크롤 양에 따라 타임라인이 앞뒤로 재생(scrub 0.8)

| 항목 | 값 |
|---|---|
| 고정 길이 | 화면 높이 × 4.4 |
| 공정마다 멈춤(snap) | 공정 하나가 끝난 자리로 부드럽게 맞춤(0.35–0.9s, 0.12s 대기, power2.inOut) |
| 진입 | 고정 전, 섹션이 화면 85% → 25% 지점을 지나는 동안 병 · 목록이 y 50 · 투명 → 제자리(scrub 0.6) |
| 시작 머무름 | 0.6 |
| 공정 1개 | **빛의 문(게이트)**이 병 왼쪽 끝에 나타나(0.45, sine.out) 빛 번짐 0.78 · 코어 0.35까지 밝아진 뒤 → **1.5 동안 왼쪽 → 오른쪽으로 지나가며** 그 공정 표면 이미지가 따라 드러남(clip-path `inset(0 100% 0 0)` → `inset(0)`) → 끝에서 빛이 사그라듦(0.55) |
| 공정 간격 | 1.9 (게이트 시작 시점 사이) |
| 목록 | 현재 공정 이름만 차콜, 나머지 회색(0.35). 진행 막대 scaleY = (n + 1) / 5 (n = 0~3, MATCH에서 1) |
| 이전 표면 | 새 표면이 다 덮은 뒤 숨김 |
| MATCH(체결) | 스포이드가 병 위(yPercent −42)에서 보임(0.35) → 1.3 동안 내려와(power2.inOut) 0.9 지점 → 0.35 동안 제자리 0(살짝 튕기듯 안착) + 목 부분에 원형 빛이 퍼짐(scale 0.5 → 1 → 1.7, 사라짐). 진행 막대 끝까지 |
| 끝 | 목록 · 병이 위로 12 · 22px 올라가며 사라지고 다음 섹션으로 |
| 공정 이름 클릭 | 그 공정이 끝난 장면 위치로 부드럽게 스크롤 |

(위 시간 단위는 타임라인 길이 기준 — 실제 체감 속도는 스크롤 속도에 따라 달라짐)

**모바일 (1024px 미만)** — 고정 없음, 스크롤과 연결하지 않음

- 화면에 들어오면(병이 화면 65% 지점) COATING 장면까지 한 번 재생(1.6s, power2.inOut).
- 이후 **공정 이름을 누르면 그 장면까지 재생**(1.4s, power2.inOut). 앞 · 뒤 어느 쪽이든 그 상태로 이동.

**스포이드 피펫 처리**: 유리 피펫은 불투명도 0.28, 라벨 높이(이미지 높이의 43.7–74.7%, 2026-10-28 라벨 사진 기준 — `src/data/home.ts` labelBand) 구간은 마스크로 가려 라벨 뒤로 들어간 것처럼 보임.

## 8. 다른 플랫폼에서 구현할 때

- **GSAP 불러오기**: `https://cdn.jsdelivr.net/npm/gsap@3.15.0/dist/gsap.min.js` + `…/dist/ScrollTrigger.min.js`(GSAP는 현재 무료 라이선스).
- **그대로 옮길 수 있는 코드**: 각 표의 구현 파일 안 `useEffect(() => { … })` 블록이 순수 GSAP 코드입니다. React 부분(`useRef`, `q("[data-…]")`)만 `document.querySelectorAll("[data-…]")`로 바꾸면 일반 HTML에서도 동작합니다.
- **이미지 좌표가 중요한 곳**: HOME 공정 모션은 병 이미지 6장이 **같은 크기(900×1600) · 같은 좌표**여야 합니다. 이미지를 바꾸면 변환 스크립트(`scripts/build-process-images.mjs`)로 맞춰야 겹침이 어긋나지 않습니다.
- **검수 방법**: 같은 화면을 실제 사이트와 나란히 띄우고, PC(1440px) · 모바일(390px) · 동작 줄이기 켬 세 경우를 비교해 주세요.
